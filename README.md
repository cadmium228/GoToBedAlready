# GoToBedAlready

Консольная утилита для Windows 10/11 с локальным веб-интерфейсом. Наблюдает за доступным прогрессом выбранного окна и выключает ПК после подтверждённых 100% и защитной задержки.

**Статус: экспериментальный выпуск. Совместимость с конкретными лаунчерами нужно проверять в тестовом режиме.**

## Скачать и запустить

Архивы Windows x64 и ARM64: [GitHub Releases](https://github.com/cadmium228/GoToBedAlready/releases).

1. Скачайте `GoToBedAlready-v0.1.0-windows-amd64.zip` для обычного Intel/AMD ПК или `windows-arm64.zip` для Windows on ARM.
2. Распакуйте **весь** архив в отдельную папку. Каталоги `web` и `scripts` должны остаться рядом с `GoToBedAlready.exe`.
3. Запустите `GoToBedAlready.exe`. Откроются консоль и браузер. Администраторские права обычно не нужны.
4. Откройте окно загрузки лаунчера. Нажмите **«Выбрать процесс»** и выберите окно с нужным индикатором.
5. Укажите задержку от 1 до 180 минут. По умолчанию — **5 минут**.
6. Сначала оставьте **тестовый режим** включённым и нажмите **«Начать»**. Проверьте, что отображаемый прогресс соответствует загрузке.
7. Для реального выключения отмените тест, выключите тестовый режим и подтвердите новый запуск. Наблюдение нужно запустить **до** достижения 100%.

Консоль должна оставаться открытой. Закрытие вкладки браузера **не отменяет** наблюдение. Кнопка отмены или `Ctrl+C` в консоли отменяет его до передачи команды Windows. После передачи `shutdown.exe /s /t 0` отмена уже невозможна. Принудительное закрытие приложений (`/f`) не используется; несохранённые документы могут заблокировать выключение. Сохраните работу заранее.

Архивы не подписаны сертификатом Authenticode; Windows SmartScreen может показать предупреждение. Контрольные суммы находятся в `SHA256SUMS.txt` рядом с архивами.

```powershell
Get-FileHash .\GoToBedAlready-v0.1.0-windows-amd64.zip -Algorithm SHA256
```

## Важное ограничение Windows

`ITaskbarList3.SetProgressValue` и `SetProgressState` позволяют приложению **устанавливать** прогресс собственной кнопки панели задач. Публичного симметричного API для чтения прогресса произвольного чужого процесса нет.

Этот проект не внедряет DLL, не перехватывает чужие COM-вызовы, не читает память процессов и не угадывает завершение по отсутствию сетевого трафика или исчезновению полосы. Используется доступный системный API **Windows UI Automation** через штатный Windows PowerShell 5.1:

- сначала единственный доступный `ProgressBar` с корректным `RangeValuePattern` внутри выбранного окна;
- затем, если такого индикатора нет, доступная кнопка панели задач с однозначно совпадающим заголовком окна и числовым `RangeValuePattern` либо процентом в accessibility-имени;
- несколько индикаторов, неоднозначный заголовок, отсутствие данных, ошибки доступа, закрытие или перезапуск процесса означают **запрет выключения** и сброс отсчёта.

Обычная цветная заливка кнопки панели задач сама по себе не является читаемым источником. На многих версиях Windows Explorer не экспортирует её процент через UI Automation. Chromium/Electron и игровые лаунчеры тоже часто не предоставляют доступный `ProgressBar`. **Работоспособность со Steam, Rockstar Games Launcher или любым другим конкретным лаунчером не гарантируется.** Имена этих приложений в демо — только иллюстрация интерфейса, не подтверждение интеграции.

Это наблюдатель доступного процента, а не проверка целостности установленной игры. Правильность назначения выбранного индикатора нужно подтвердить тестом. При нескольких загрузках безопаснее оставить одну. Если лаунчер сразу скрывает 100% или закрывает индикатор, выключения не произойдёт. Для гарантированной поддержки такого лаунчера нужен отдельный адаптер его API/манифестов, а не выдуманный универсальный WinAPI getter.

## Защита от преждевременного выключения

- Сначала должен быть увиден прогресс **ниже 100%**, затем ровно 100% из того же источника.
- На протяжении всей задержки требуется последовательность доступных показаний 100%. Опрос — каждые 3 секунды, тайм-аут Windows UI Automation — 12 секунд. Это дискретное наблюдение: изменения между опросами не могут быть обнаружены.
- Докачивание, потеря данных и длительный перерыв между опросами сбрасывают отсчёт. Возобновление после сна не приводит к немедленному выключению.
- Изменение идентификатора индикатора требует заново увидеть прогресс ниже 100%.
- PID проверяется вместе со временем запуска, чтобы не наблюдать другой процесс после повторного использования PID.
- Отмена инвалидирует незавершённый запрос наблюдения. Его поздний результат не может выключить ПК или повлиять на новую сессию.
- Ошибка команды выключения не вызывает автоматических повторных попыток.
- Наблюдение не восстанавливается автоматически после перезапуска приложения.
- Приложение не блокирует системный сон. При необходимости настройте план электропитания Windows самостоятельно.

## Дополнительные возможности

- Безопасный тестовый режим, включённый по умолчанию.
- Отдельный демонстрационный режим с искусственным прогрессом и двумя независимыми блокировками реального выключения.
- Журнал последних 50 переходов состояния.
- Сохранение задержки, режима и журнала в `%APPDATA%\GoToBedAlready\settings.json`.
- Поиск процессов по имени, PID и заголовку окна.
- Обратный отсчёт, источник прогресса и объяснение причин блокировки выключения.
- Локальные HTML/CSS/JavaScript без CDN, аналитики, внешних шрифтов и npm-зависимостей приложения.
- Клавиатурная навигация, видимый фокус, адаптивная вёрстка, поддержка `prefers-reduced-motion`.

## Безопасность локального интерфейса

В рабочем режиме сервер слушает только loopback IP на случайном порту. Ссылка содержит случайный 256-битный токен во фрагменте URL. Интерфейс переносит его в `sessionStorage`, очищает фрагмент и передаёт токен в заголовке API. Токен не сохраняется на диск приложением.

Запросы API требуют токен. Проверяются `Host` и `Origin`, отсутствует CORS-разрешение сторонних сайтов. Изменение состояния доступно только через POST. Ограничены размер тела, заголовков и тайм-ауты запросов. Названия процессов вставляются через `textContent`. Не публикуйте ссылку из консоли и не передавайте её посторонним. Защита не предназначена для противодействия вредоносному ПО с доступом к вашей пользовательской сессии.

В `-demo` допускается публичный адрес для превью и API не требует токена. В этом режиме реальные процессы не читаются, реальное выключение заблокировано, а настройки хранятся отдельно с суффиксом `.demo`.

PowerShell запускается с `-NoProfile -NonInteractive -ExecutionPolicy Bypass` только для поставляемого скрипта; системная ExecutionPolicy не изменяется. Корпоративные AppLocker/WDAC/Constrained Language политики могут запретить запуск. Скрипт не требует повышения привилегий, но лаунчер, запущенный от администратора, может быть недоступен обычному процессу. Не повышайте права ради непроверенного наблюдения.

## Разработка

Требуются Go 1.23+ и Python 3 для упаковки. В CI используется Go 1.26.9. Внешних Go-модулей и `go.sum` нет.

```bash
go test -race ./...
go vet ./...
node --check web/app.js
go run ./cmd/gotobedalready -demo -assets . -open=false -listen 127.0.0.1:8080
```

Демонстрация доступна на Linux, macOS и Windows. Прогресс начинается с 24% при первом опросе, примерно за минуту доходит до 100%, затем удерживается. Для повторения демонстрационной загрузки перезапустите демо-сервер. Для короткого полного теста установите задержку 1 минуту.

Запуск реального наблюдения из исходников на Windows:

```powershell
go run ./cmd/gotobedalready -assets .
```

Все параметры:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `-listen` | `127.0.0.1:0` | Адрес HTTP; не-loopback разрешён только с `-demo` |
| `-assets` | папка исполняемого файла | Корень, содержащий `web/` и `scripts/` |
| `-data` | пользовательский каталог конфигурации | Файл настроек и журнала |
| `-demo` | `false` | Искусственный прогресс, без выключения |
| `-open` | `true` | Автоматически открывать браузер на Windows |

## Сборка релиза

Из корня репозитория:

```bash
python scripts/build.py --version v0.1.0
```

Скрипт кросс-компилирует консольные PE-файлы без CGO для Windows amd64 и arm64, упаковывает необходимые ресурсы и README, добавляет сведения о версии/коммите/toolchain и формирует SHA-256. Артефакты находятся в игнорируемом `dist/`. Не переносите EXE отдельно от ресурсов.

Workflow `Verify and package` запускает race-тесты и vet на Linux и Windows, проверяет синтаксис PowerShell и чтение реального WPF ProgressBar (25% → 100%) через UI Automation на Windows, собирает оба архива. Он не выключает машину. Обычный push не публикует релиз. Ручной запуск workflow с параметром `publish=true` после успешных тестов загружает проверенные архивы в заранее созданный draft `v0.1.0` и публикует его как prerelease. Для интеграций без разрешения `actions: write` предусмотрен такой же явный запуск публикации push-коммитом с точным сообщением `Release GoToBedAlready v0.1.0` только в ветке `arena/676301c3-gotobedalready`. Право `contents: write` выдано только шагу публикации; он всегда зависит от успешных проверок и сборки. Совместимость с реальными Steam/Rockstar и разными версиями Explorer требует ручного тестирования на Windows; компиляция и тесты бизнес-логики этого не доказывают.

## Архитектура

```text
cmd/gotobedalready/       composition root, жизненный цикл консоли и HTTP
internal/domain/         модели и инварианты
internal/monitor/        машина состояний, orchestration, порты зависимостей
internal/platform/       Windows UI Automation, power adapter, безопасное демо
internal/storage/        JSON repository, замена файла через временный файл
internal/config/         флаги, значения по умолчанию, проверка адреса и ресурсов
internal/httpui/         HTTP API, авторизация, статические ресурсы
web/                     доступный интерфейс без фреймворка
scripts/observe.ps1       адаптер системного Windows UI Automation
scripts/build.py         упаковка бинарников и контрольных сумм
.github/workflows/       проверка и сборка
```

`monitor` зависит от узких интерфейсов `Observer`, `PowerController`, `Repository`, а не от HTTP, PowerShell или файловой системы. `httpui` зависит от интерфейса `Monitor`. Подстановка адаптера не меняет правила завершения. Чистая машина состояний получает время аргументом, тестируется без реального ожидания. Синхронизация и побочные эффекты вынесены в сервис. Тестовые реализации не вызывают системное выключение.

В исходном коде нет комментариев, build tags и embed-директив. Windows-специфичная конфигурация subprocess выбирается суффиксом `_windows.go`. Ресурсы поставляются отдельными файлами, чтобы не использовать комментарий-директиву `go:embed`.

Визуальная система: тёмная локальная утилита, лавандовый акцент, чёткая иерархия и низкая визуальная нагрузка. При проектировании использованы рекомендации [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) по доступности, размеру интерактивных областей, состояниям загрузки и responsive layout.
