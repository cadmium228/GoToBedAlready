# GoToBedAlready

Локальная утилита для Windows 10/11: выключение ПК после завершения доступного индикатора загрузки. Ветка v0.2 использует собственное окно **WinForms + WebView2**, а не вкладку браузера. Бизнес-логика, HTTP API, хранилище и управление питанием написаны на Go.

## Текущая версия

Версия **v0.2.0**, предварительный релиз. Windows-архивы amd64 и arm64 опубликованы в [GitHub Releases](https://github.com/cadmium228/GoToBedAlready/releases). Предыдущий релиз v0.1.0 не изменялся.

CI проверяет код на Linux и Windows: unit/race-тесты, `go vet`, форматирование, синтаксис JavaScript и PowerShell. Windows-job также компилирует C# WebView2-хост, читает реальный WPF `ProgressBar` через UI Automation (25% → 100%) и запускает собранную demo-сборку. **Физическое гашение монитора, окно WebView2 на конкретном ПК и совместимость с реальными лаунчерами, включая Rockstar, всё ещё требуют ручной проверки.**

## Запуск

Скачайте `GoToBedAlready-v0.2.0-windows-amd64.zip` для обычного Intel/AMD ПК или `windows-arm64.zip` для Windows on ARM.

1. Распакуйте весь архив, сохранив папки `web`, `scripts`, `runtime` рядом с `GoToBedAlready.exe`.
2. Установите Microsoft Edge WebView2 Runtime, если его нет: https://developer.microsoft.com/en-us/microsoft-edge/webview2/
3. Запустите EXE. Он собран как Windows GUI; консоль и браузер не открываются. WebView2 работает внутри отдельного окна программы.
4. Выберите процесс и задержку (1–180 минут, по умолчанию 5). Нажмите «Начать» и подтвердите выключение.
5. «Остановить» отменяет наблюдение. Закрытие окна тоже отменяет наблюдение, останавливает backend и освобождает запросы питания.

Требуется Windows PowerShell 5.1 и .NET Framework 4.8 (4.8.1 для нативного ARM64-хоста). Поддерживаемые современные Windows обычно включают их. Для GUI запускается скрытый PowerShell-хост, который загружает небольшой C# WinForms/WebView2 wrapper. Браузер как запасной вариант **не запускается**. Если WebView2 отсутствует или корпоративная политика запрещает PowerShell/Add-Type, приложение показывает ошибку и завершает работу.

Тумблера тестового режима в интерфейсе нет. Обычный старт означает реальное выключение. Сохраните документы заранее. Используется `shutdown.exe /s /t 0`, без `/f`; несохранённые документы могут помешать выключению. После передачи команды ОС отмена не гарантируется.

## Процессы и Rockstar

В v0.1.0 список ошибочно ограничивался процессами с `MainWindowHandle != 0`. Поэтому `Launcher.exe` без собственного окна отсутствовал, а окно лаунчера отображалось как `SocialClubHelper.exe`.

Новый список включает доступные процессы текущей пользовательской сессии, даже без окна. Чтение прогресса рассматривает все видимые верхнеуровневые окна выбранного процесса **и его потомков**. При выборе SocialClubHelper используется его реальный предок Launcher, только если связь подтверждается деревом PID и временем создания процессов. Одно лишь совпадение имени файла не объединяет независимые процессы.

Доступные источники:

- UI Automation `ProgressBar` с `RangeValuePattern` или процентным `ValuePattern`;
- стандартный Windows `msctls_progress32`, в том числе вложенный WinForms-контрол: `PBM_GETPOS`, `PBM_GETRANGE`, `PBM_GETSTATE` через ограниченные по времени Win32-вызовы; paused/error/marquee не принимаются за завершение;
- однозначная кнопка панели задач с доступным числовым значением или процентом в accessibility-имени.

**Это не гарантированная интеграция Rockstar.** Chromium/CEF-контрол может вообще не предоставлять процент. WinAPI не содержит универсального getter для прогресса чужого `ITaskbarList3`. Исправление списка и связи процессов не создаёт отсутствующий источник данных.

Если после выбора Launcher или его helper остаётся ошибка, откройте экран загрузки и нажмите **«Сохранить диагностику»**. Файл содержит выбранный PID, проверенное семейство процессов, найденные окна, до 150 UIA-элементов и результат чтения. Перед отправкой проверьте заголовки и текст элементов: они могут содержать личную информацию. Файл никуда автоматически не отправляется. По диагностике можно определить, нужен ли специальный адаптер логов/манифестов конкретного лаунчера. Неизвестный формат логов не угадывается.

## Управление питанием

### Гасить экран

Работает только при включённом переключателе **и активном наблюдении**. Экран гасится при старте. Мышь или клавиатура пробуждает экран штатным механизмом Windows; после десяти секунд без нового ввода экран гасится снова. Проверяется `GetLastInputInfo`, без глобальных клавиатурных hook и без записи клавиш.

При отмене, выключении переключателя или закрытии приложения экран, который приложение пыталось погасить, включается обратно. Это команда ОС для дисплеев, не аппаратное выключение питания; поведение конкретных мониторов, драйверов, удалённых сессий и Modern Standby требует проверки.

### Отключить таймауты

По умолчанию включено. Пока приложение открыто, `SetThreadExecutionState` запрашивает отсутствие автоматического сна и автоматического гашения экрана. Во время намеренного гашения первым переключателем требование держать дисплей включённым снимается, а требование не усыплять ПК остаётся.

Запрос живёт на отдельном закреплённом OS thread; при завершении он освобождается. План питания и реестр не меняются. Это **не** отмена ручного сна/блокировки, shutdown-задач других программ, Windows Update, критического заряда батареи, screen saver или принудительных корпоративных политик. Приложение не вызывает глобальный `shutdown /a` и не вмешивается в чужие задания.

## Условия выключения

Нужен переход из прогресса ниже 100% к ровно 100% из одного источника, затем доступные 100% всю задержку. Докачивание, потеря данных, смена индикатора, перезапуск процесса и длительная пауза опроса сбрасывают отсчёт. Исчезновение индикатора не считается завершением.

Опрос дискретный, каждые 3 секунды, тайм-аут чтения 12 секунд. Изменения между опросами могут быть не обнаружены. Это наблюдение индикатора, не проверка целостности игры. При нескольких индикаторах выключение блокируется. После перезапуска программы наблюдение не возобновляется автоматически.

## Интерфейс

Одна колонка без левой панели, орбит, лозунгов, журнала, карточек с дублирующими метриками и сообщений «наблюдение не запущено/отменено». Прогресс и обратный отсчёт появляются только во время наблюдения. Ошибки чтения, записи настроек и питания остаются видимыми.

Дизайн и применение UI-UX-PRO-MAX / Anthropic frontend-design: `docs/design.md`.

## Сборка и проверки

Требуются Go 1.23+ и Python 3. Внешних Go-модулей нет. Во время сборки скачиваются только WebView2 SDK DLL из зафиксированного pywebview wheel с проверкой SHA-256. Python и pywebview не нужны на целевом компьютере. DLL не хранятся в Git.

```bash
python scripts/fetch_webview.py
go test -race ./...
go vet ./...
node --check web/app.js
python scripts/build.py --version v0.2.0-local
```

Архивы и SHA256SUMS находятся в `dist/`. Сборка использует `-H=windowsgui`. Сведения о commit и локальных изменениях записываются в `BUILD.txt`. SDK лицензии включены в архив; происхождение DLL описано в `runtime/webview2/THIRD_PARTY.md`. EXE не подписан Authenticode, поэтому SmartScreen может показать предупреждение; контрольные суммы находятся в `SHA256SUMS.txt`.

Windows-тесты проверяют компиляцию C# хоста, чтение WPF-индикатора, наличие безоконного процесса в списке и PowerShell-синтаксис. Они требуют Windows и подготовленного SDK. Тесты политики питания используют fake Device и не выключают реальный монитор или ПК.

CI на push и pull request только тестирует и собирает предварительные архивы. Публикация выполняется вручную после merge в `main`:

```bash
gh workflow run "Verify and package" --ref main -f version=v0.2.0 -f publish=true
```

Job дожидается успешных тестов и сборки, создаёт prerelease с обоими архивами и `SHA256SUMS.txt` и отказывается перезаписывать уже существующий релиз, включая v0.1.0.

Разработка на Linux/macOS, без доступа к реальному питанию или процессам Windows:

```bash
go run ./cmd/gotobedalready -demo -assets . -open=false -listen 127.0.0.1:8080
```

В `-demo` прогресс искусственный, выключение ПК и управление монитором заблокированы на backend. Только здесь есть небольшая отметка «Предпросмотр». Тестовый режим для службы остаётся внутренней защитой и тестовым инструментом, а не пользовательским переключателем.

Параметры: `-assets` — корень ресурсов; `-data` — JSON настроек; `-listen` — HTTP адрес (не-loopback разрешён только для demo); `-open=false` — не создавать native окно, только режим разработки. По умолчанию приложение слушает случайный loopback порт. API защищён случайным токеном, Host/Origin-проверками и ограничениями запросов. WebView2 не разрешает внешнюю навигацию, новые окна, host objects и запросы привилегий.

Настройки: `%APPDATA%\GoToBedAlready\settings.json`. WebView2-профиль: `%LOCALAPPDATA%\GoToBedAlready\WebView2`. Журнал службы сохраняется в JSON для диагностики, но больше не выводится в интерфейсе.

## Пакеты

```text
cmd/gotobedalready    composition root, запуск и закрытие окна/сервера
internal/domain      модели
internal/monitor     машина состояний, порты наблюдения/выключения/хранилища
internal/energy      чистая политика экрана, lifecycle lease, Win32-адаптер
internal/desktop     lifecycle WebView2 host
internal/httpui      локальный API, сессия, ресурсы
internal/platform    Windows progress observer, shutdown, demo
internal/storage     JSON repository и миграция значений по умолчанию
internal/config      аргументы запуска
scripts              Windows bridge, WebView2 host, получение SDK, упаковка
web                  HTML/CSS/JS интерфейс
```

Комментарии в исходный код не добавлены. Windows-реализации выбираются именами `*_windows.go`; embed/build-директив нет, ресурсы поставляются отдельными файлами.
